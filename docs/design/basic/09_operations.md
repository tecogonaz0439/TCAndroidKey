## 1. 運用上の原則

- **テスト用途に限定する** (PRE-01)。テスト用 RP・テスト用アカウントにのみ登録する。
- **物理キーの代替にしない** (PRE-02)。本番サービス・業務システムの本番環境・個人の重要アカウントには登録しない。
- テスト終了後は不要なクレデンシャルを削除する。

## 2. 導入

| 手順 | 内容 |
|---|---|
| 1 | 端末が Android 15 以上・NFC (HCE) 対応であることを確認する |
| 2 | 画面ロック (PIN / パターン / パスワード) と指紋 (Class 3 生体認証) を設定する。画面ロックがないと鍵を生成できない |
| 3 | NFC をオンにする |
| 4 | APK をインストールする (adb、または MDM によるサイドロード) |
| 5 | アプリを起動し、「本人確認して開始」で受付状態になることを確認する |
| 6 | 他に FIDO の AID を登録した HCE アプリがある場合、OS の確認ダイアログで本アプリを選ぶ (前面表示中は本アプリが優先される) |

## 3. 日常の利用

1. テスト対象の Web アプリで登録 / ログインを開始する。
2. 本アプリを開いて「本人確認して開始」→ 指紋認証。
3. 受付時間内に端末をリーダーにかざす (または端末同士を重ねる)。
4. 結果をイベントログで確認する (RP ID、コマンド、ステータス)。

## 4. 更新

- **上書きインストールで更新する** (`adb install -r`)。アンインストールすると全クレデンシャルが失われる。
- debug 版と release 版は署名が異なるため、相互に上書きできない。
- 旧名 TCAndroidKey (パッケージ `net.tecogonaz.tcandroidkey`) からは上書きできない (別アプリ)。旧版をアンインストールしてから
  インストールし、鍵を再登録する。同じ FIDO AID を登録したアプリが 2 つ残っていると、どちらが応答するかが不定になる。

## 5. 鍵が失われる操作 (注意事項)

| 操作 | 影響 |
|---|---|
| アプリのアンインストール / アプリデータの消去 | 全クレデンシャルが削除される |
| 端末の初期化 | 同上 |
| 画面ロックの解除 (無効化) | Keystore の鍵が無効化され、使用できなくなる場合がある |
| 本アプリの「すべて削除」/ OS からのリセット (許可時) | 全クレデンシャルが削除される |

いずれも復旧手段はない (PRE-04)。RP 側にテスト用アカウントの別の認証手段 (パスワード等) を用意しておく。

## 6. 障害時の切り分け

| 症状 | 確認事項 |
|---|---|
| リーダーにかざしても反応しない | NFC がオンか。アプリが前面表示中か。受付状態 (残り秒数) か。イベントログに "reader detected" が出ているか |
| "before verification" がログに出る | 本人確認前にかざしている。確認後に一度離してから再度かざす |
| 登録時に失敗 (`OPERATION_DENIED`) | 画面ロックが設定されているか。受付時間が切れていないか |
| 認証時に `NO_CREDENTIALS` | その RP のクレデンシャルが本端末にない (別端末・削除済み) |
| ブラウザが認識しない | クライアントの対応状況 (BD-04 §5) を確認する。python-fido2 で CTAP レベルの応答を確認する |
| RP が PIN を要求して先に進めない | 本アプリは clientPIN 非対応 (AP-C)。RP の userVerification 設定を確認する |

## 7. 利用終了

1. クレデンシャル画面で「すべて削除」を実行する (本人確認あり)。
2. RP 側のテスト用アカウントから、本認証器の登録を削除する。
3. アプリをアンインストールする。
