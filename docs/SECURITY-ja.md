# セキュリティポリシー

**最終更新日: 2026-11-05**

## 1. 目的と適用範囲

本ポリシーには日本語版と英語版 ([Security Policy](../SECURITY.md)) があります。両者の内容に相違がある場合は、日本語版が優先します。

本ポリシーは、**セキュリティキーエミュレータ** (英語名 Security Key Emulator、プロジェクト名 TCSecurityKeyEmulator。以下「本アプリ」) のセキュリティ上の位置付け、保護の仕組み、既知の制約、利用者に求める対策、および脆弱性の報告方法を定めます。

## 2. セキュリティ上の位置付け

本アプリは、**FIDO / FIDO2 (WebAuthn) を使用する Web アプリケーションの試験用ツール**です。本アプリの保護の仕組みは、試験中の誤操作や意図しない認証を防ぐことを目的としており、YubiKey などの物理セキュリティキーと同等の安全性を提供するものではありません。

物理セキュリティキーと異なる主な点は次のとおりです。

- 認証処理は専用のハードウェアではなく、Android 上のアプリとして動作します。端末の OS や本アプリ自体の脆弱性の影響を受けます。
- FIDO Alliance の認定 (FIDO Certified) を受けていません。
- 認証器の真正性を示すアテステーション (ベンダーの証明書) を持ちません。
- 鍵のバックアップ・移行・復元はできません。

このため、**本アプリを物理セキュリティキーの代替として使用せず、試験用のアカウント・環境にのみ登録してください** ([利用規約](TERMS-ja.md) 第 2 条・第 3 条)。

## 3. 保護の仕組み

| 項目 | 内容 |
|---|---|
| 秘密鍵の保管 | 登録ごとに Android Keystore (StrongBox を優先し、非搭載の場合は TEE) の中で EC P-256 鍵を生成します。鍵は端末外へ取り出せません |
| 本人確認 | 登録・認証の前に、指紋等の生体認証 (Class 3) または画面ロックの資格情報による本人確認が必要です |
| 受付の制限 | 本アプリの画面が前面に表示されている間、かつ本人確認後の受付時間 (15〜300 秒、既定 60 秒) の間のみ応答します。既定では本人確認 1 回につき登録・認証 1 回のみ (ワンタイム) です |
| 受付外の動作 | 受付外では NFC の FIDO アプレット自体を見せません (存在しないように振る舞います) |
| 停止・前面離脱 | 受付の停止、または本アプリが前面から外れた時点で、実行中・継続中の操作も無効にします |
| 端末ロック | 端末のロック中は、NFC の応答と鍵の使用のどちらも OS により禁止されます |
| 鍵の利用期限 | 鍵は、ユーザー認証から 300 秒以内、かつ端末のロック解除中のみ署名に使用できます (Android Keystore による多重防御) |
| メタデータ | RP ID・ユーザー名等のメタデータは、Android Keystore の AES-256-GCM 鍵で暗号化して保存します |
| PIN | クライアントから設定された PIN は、切り詰めた SHA-256 のハッシュと試行回数のみを、Android Keystore の AES-256-GCM 鍵で暗号化して保存します。PIN の照合は受付時間内のみ受け付け、試行は 8 回まで、連続 3 回の誤りでは再接続が必要です |
| バックアップ | すべてのデータを Android のバックアップ・端末移行の対象外としています |
| 画面 | スクリーンショット・画面共有を禁止しています |
| ログ | イベントログはメモリ内のみに保持します。システムログ (logcat) には RP ID・ユーザー名・接続先の名前を出力しません |
| 通信 | インターネットへの通信を行いません |
| 削除・保護設定 | 鍵の削除、PIN の消去、およびワンタイム OFF 等の保護を弱める設定変更には本人確認が必要です |

## 4. 既知の制約と残存リスク

本アプリは試験用ツールとして、次の制約・リスクを受容しています。これらは脆弱性としては扱いません。

| 制約・リスク | 内容 |
|---|---|
| 要求元の識別 | 受付時間内は、近くの NFC リーダー等からの要求を区別できません。ワンタイムでも、最初に要求してきた悪意あるリーダーを選別することはできません |
| アプリとしての動作 | 認証処理はアプリのプロセス上で動作するため、OS・本アプリの脆弱性や、root 化等により改変された端末の影響を受けます |
| 共通の debug 署名鍵 | 開発用ビルドは、リポジトリで公開している共通の署名鍵で署名しています。同じ鍵で署名された悪意ある APK を更新としてインストールすると、本アプリのデータと鍵を引き継いで使用できる可能性があります |
| メタデータの巻き戻し | 暗号化されたメタデータの改ざん・破損は検出しますが、以前の正当なファイルへの置き換え (署名カウンタの巻き戻し) は検出しません |
| PIN | PIN のハッシュは切り詰めた SHA-256 のため、PIN のファイルと Keystore の鍵の両方を取り出せる攻撃者は、短い PIN をオフラインで総当たりできます。PIN がブロックされても、端末での本人確認 (生体認証・画面ロック) は引き続き使えます。試験用の PIN を使ってください |
| アテステーション | ベンダーのアテステーションを持たず、`none` または自己アテステーションのみに対応します |
| Bluetooth HID | 実験的機能です。ホストの環境によっては動作しません |
| 開始済みの鍵操作 | 受付の停止前に開始した Keystore の操作そのものは取り消せません (停止後は新たな鍵操作を開始せず、結果を送出しません) |

## 5. 利用者に求める対策

- 端末に画面ロックを設定し、OS を最新の状態に保ってください。
- 本アプリは、自ら作成した APK、または開発者から直接入手した APK のみをインストールしてください。
- 本番サービスや重要なアカウントには登録せず、試験用のアカウント・環境のみで使用してください。
- 試験が終わった鍵は削除してください。本アプリを使用しなくなった場合は、アンインストールしてください (すべての鍵が削除されます)。
- 本アプリの受付中 (「認証できます」の表示中) は、端末から目を離さないでください。

## 6. サポート対象のバージョン

セキュリティ上の修正は、最新版 (リポジトリの最新のソースコード) に対してのみ行います。

## 7. 脆弱性の報告

本アプリの脆弱性を発見した場合は、公開の Issue を作成せず、メールで [tecogonaz@kusugami-lab.net](mailto:tecogonaz@kusugami-lab.net) へご報告ください。可能な限り速やかに対応します。

報告には、可能な範囲で次の情報を含めてください。

- 対象のバージョン (コミット) と端末・Android のバージョン
- 再現手順、および想定される影響
- 使用したクライアント (OS・ブラウザ・NFC リーダー等)

第 4 節の既知の制約・残存リスク、および root 化・改変された端末や第三者が作成した APK に起因する事象は、原則として対象外とします。

当方は、すべての報告への個別回答、修正、修正時期を保証しません。

## 8. 本ポリシーの変更

本ポリシーは、本アプリ、利用環境、法令等の変更に応じて更新する場合があります。変更内容と最終更新日は、ソースコードリポジトリに掲載します。
